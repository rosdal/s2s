# s2s — Todo 3: Stage 2 Source maps

Nov 2, 2026 · @Mark

## Goal

This todo makes `s2s maps` turn every source map in a capture into recovered original files, package evidence and project hints. It also reports how much first-party code is still unexplained, so the next stages only work on the remainder. Everything here is offline: it reads `raw/` and writes `recovered/` and `analysis/`.

**Done when**

- On the `sourcemaps` fixture, every file whose map has `sourcesContent` comes back byte-identical to the fixture's source, at its original relative path
- On the partial-map fixture, identifiers in the minified chunk are renamed to their original names wherever the map has them
- pnpm, npm and yarn-style `node_modules` paths yield correct package names, and exact versions wherever the path carries them
- `analysis/sourcemaps.json` reports coverage: the share of first-party JS and CSS bytes explained by exact sources
- A workspace with no maps finishes cleanly with coverage 0% and stage status `complete`
- Rerunning is a no-op; `--force` rebuilds `recovered/sourcemap/` from scratch

## Decisions

| Decision           | Recommendation                                                                                                                                              | Why                                                                          |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Map parser         | `@jridgewell/trace-mapping` (handles index maps with `sections`)                                                                                            | Fast, small, used by Vite, Babel and Jest                                    |
| Path normalization | Strip known prefixes (`webpack://<ns>/`, `./`, `/@fs/`, `vite:`), resolve `..`, then cut the longest common prefix of first-party paths as the project root | Turns build-machine absolute paths into `src/...`-style relative paths       |
| Virtual modules    | `webpack/runtime/*`, `\0`-prefixed and `vite/*` sources go to `_virtual/`, never into `src/`                                                                | They are bundler internals, not the author's code                            |
| Vendor sources     | Not written into the project tree; kept under `recovered/sourcemap/_vendor/` for reference and emitted as package evidence                                  | Stage 3 turns them into dependencies, not copied files                       |
| Path conflicts     | Same path, same content: keep one. Same path, different content (two builds, A/B bundles): keep both with a short hash suffix and list them in the report   | Never silently drops code                                                    |
| Partial maps       | Rename identifiers in the minified chunk using the map's `names`, write the result to `recovered/renamed/`, and record original-file boundaries             | Renaming must happen on original positions, before Stage 4 rewrites the code |
| Confidence labels  | `exact` (sourcesContent), `renamed` (names only), `none`                                                                                                    | Lets AGENTS.md tell the agent what to trust                                  |
| CSS maps           | Same pipeline; recovers `.scss`, `.less` and `.module.css` sources                                                                                          | Preprocessor sources are often in CSS maps even when JS maps are missing     |

## Checklist

**1. Collect maps**

- [x] Check that capture follows the `SourceMap` / `X-SourceMap` headers and `sourceMappingURL` comments, not only `<file>.map` probing; patch Todo 2 if a case is missing
- [x] Load maps from `raw/maps/`, and extract inline `data:` maps from JS and CSS bodies
- [x] Link each map to its generated file by URL and record the pair in the report
- [x] Validate each map (JSON, version 3, mappings decode); list unusable maps with the reason instead of failing the stage
- [x] Flatten index maps (`sections`) into one logical map per generated file

**2. Normalize paths**

- [x] Apply the prefix rules and `..` resolution from Decisions
- [x] Classify each source as `first-party`, `vendor` (contains `node_modules`) or `virtual`
- [x] Detect the project root as the longest common prefix of first-party paths; make everything relative to it
- [x] Reject paths that escape the output folder after normalization (`../` tricks in a hostile map)

**3. Write exact sources**

- [x] Write each first-party source with `sourcesContent` to `recovered/sourcemap/<path>`
- [x] Dedupe by path and content hash; suffix and report real conflicts
- [x] Write virtual sources to `_virtual/` and vendor sources to `_vendor/`

**4. Package evidence**

- [x] Parse package name and version from vendor paths:
  - npm/yarn classic: `node_modules/<name>/...` and `node_modules/@scope/<name>/...` (name only)
  - pnpm: `node_modules/.pnpm/<name>@<version>/node_modules/<name>/...` (exact version)
  - Yarn PnP: `.yarn/cache/<name>-npm-<version>-<hash>.zip/...` (exact version)
  - Nested `node_modules` (a dependency's own dependency) recorded with its parent
- [x] Detect the package manager from those path shapes and store it as a hint for the default `--pm`
- [x] Write `analysis/evidence/sourcemap-packages.json`: name, version or null, files seen, total bytes, source `sourcemap`

**5. Partial maps**

- [x] For maps without `sourcesContent`: parse the generated chunk, and for every binding whose position maps to an original name, rename the binding through its scope (all references together)
- [x] Skip a rename when it would shadow or collide with another binding; log skipped renames
- [x] Write the renamed chunk to `recovered/renamed/<body-hash>.js`; Stage 4 prefers it over the raw body
- [x] Record which generated ranges came from which original file in `analysis/sourcemap-boundaries.json`, so Stage 4 can split modules along real file lines

**6. Project hints**

- [x] Language: share of `.ts`/`.tsx` versus `.js`/`.jsx` sources
- [x] Framework from file patterns: `app/` or `pages/` routes, `.vue`, `.svelte`, `.astro`, `routes/` with loaders
- [x] Styling: `.scss`, `.less`, `.module.css`, `tailwind` imports
- [x] Path aliases: imports like `@/components` that resolve to a `src/` folder
- [x] Write `analysis/project-hints.json` with each hint, its evidence and a confidence

**7. CLI and reporting**

- [x] `s2s maps` with `--force`; reads and updates the stage status in `manifest.json`
- [x] Coverage: map every first-party generated byte to `exact`, `renamed` or `none`, and store totals per file and overall
- [x] One-line summary, for example "38 maps, 214 sources recovered, 71% of first-party JS covered"

## Output

This stage adds the following to the workspace; `raw/` is never modified.

```
<workspace>/
├── recovered/
│   ├── sourcemap/
│   │   ├── src/...              exact first-party sources, original paths
│   │   ├── _virtual/            bundler internals
│   │   └── _vendor/             node_modules sources, reference only
│   └── renamed/<body-hash>.js   chunks renamed from partial maps
└── analysis/
    ├── sourcemaps.json          maps found, pairs, errors, conflicts, coverage
    ├── sourcemap-boundaries.json
    ├── project-hints.json       language, framework, styling, aliases, pm
    └── evidence/
        └── sourcemap-packages.json
```

## Tests

Each fixture is built from known source and run through `capture` then `maps`. Its test compares recovered output against the original files.

| Fixture                    | Built with                                                                                               | Proves                                                   |
| -------------------------- | -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| `sourcemaps` (from Todo 2) | Vite, `sourcemap: true`, one unlinked map                                                                | Exact recovery, byte-identical, at the original paths    |
| `sourcemaps-partial`       | esbuild, `sourcesContent: false`                                                                         | Scope-safe renames and boundary records                  |
| `sourcemaps-inline`        | esbuild, `sourcemap: "inline"`                                                                           | Inline `data:` extraction                                |
| `webpack-namespace`        | webpack 5 with `devtoolNamespace` and runtime modules                                                    | `webpack://` prefix rules and `_virtual/` routing        |
| `pnpm-vendor`              | Vite app installed with pnpm, maps include vendor sources                                                | `.pnpm` path parsing with exact versions; pm hint = pnpm |
| `css-preprocessor`         | Sass and esbuild with SCSS and CSS Modules, CSS maps on (Vite 8 writes no CSS maps in production builds) | `.scss` and `.module.css` recovery; styling hints        |
| `hostile-map`              | Hand-written maps: `../../etc` paths, broken mappings, conflicting duplicates                            | Path-escape rejection, error listing, conflict suffixing |

Unit tests cover each path-normalization rule, every `node_modules` path shape, the project-root finder and the coverage calculation.

## Not in this todo

- Turning package evidence into `package.json` (Stage 3 merges every evidence source)
- Unbundling or splitting chunks; this stage only records boundaries for Stage 4
- Guessing names where the map has none (that is the agent's job in Stage 5)
