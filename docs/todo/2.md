# s2s — Todo 2: Stage 1 Capture

Nov 2, 2026 · @Mark

## Goal

This todo makes `s2s capture <url>` produce a complete, resumable workspace. The workspace holds every request the site made, every JS/CSS chunk it could have loaded, both HTML states, runtime facts and baseline screenshots. Stages 2–5 read only from this workspace and never hit the network again, so whatever capture misses is gone for good.

**Done when**

- `s2s capture <url>` writes a workspace with `manifest.json` marking capture `complete`, plus everything under `raw/` listed in Output below
- On every local fixture site, 100% of the JS and CSS chunks are captured, including ones the page never loads during the session
- Running it again on a finished workspace is a no-op; `--force` recaptures, and stored bodies stay deduplicated by hash
- A run interrupted with Ctrl+C leaves capture marked `partial` and can be restarted cleanly
- It runs without crashing on at least three real sites of different stacks (for example a Vite SPA, a webpack/React site and an Astro or static site), with a short notes file per site on what was missed

## Decisions

| Decision                      | Recommendation                                                                                                                                 | Why                                                                                |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Browser                       | `playwright-core`; use an installed Chrome (`channel: "chrome"`) if found, otherwise ask to run `npx playwright install chromium` on first use | Keeps `npx @rosdal/s2s` fast; no 150 MB download baked into install                |
| Service workers               | Blocked (`serviceWorkers: "block"`)                                                                                                            | A service worker serves cached responses that page-level listeners never see       |
| Body storage                  | Own store: `raw/bodies/<sha256>` plus a `requests.jsonl` index                                                                                 | Dedup across pages and reruns; easy for later stages to stream                     |
| HAR                           | Also written, via `--har` (off by default)                                                                                                     | Interop with DevTools and other tools, not the source of truth                     |
| "Page done" signal            | Network quiet for 1 s, capped at 30 s per phase (both configurable)                                                                            | `networkidle` hangs on sites with polling, analytics beacons or websockets         |
| Navigation during interaction | Main-frame navigations aborted while triggering lazy code                                                                                      | Clicking menus must not leave the page                                             |
| Manifest                      | `zod` schema in `core`, with a `schemaVersion` field                                                                                           | Later stages validate before reading; migrations stay possible                     |
| Domain logic                  | `tldts` for registrable domain (first-party vs third-party)                                                                                    | `www.shopify.com` and `cdn.shopify.com` are both first-party                       |
| robots.txt                    | `robots-parser`; respected by default, `--ignore-robots` prints a warning                                                                      | Matches the polite defaults in the design                                          |
| Concurrency                   | `p-limit`, default 4 parallel fetches, 1 s between crawled pages                                                                               | Polite, still fast enough                                                          |
| CLI framework                 | citty                                                                                                                                          | Typed subcommands with little boilerplate; settles the open choice from the design |

## Checklist

Build in this order. The fixtures come early, so each step after them is tested as it lands.

**1. Workspace and manifest (`core`)**

- [x] Workspace folder naming: a slug of host + path (`shopify-com-editions-winter2026`), overridable with `--out`
- [x] `manifest.json` schema: `schemaVersion`, s2s version, target URL, options used, and per stage `status` (`pending` / `partial` / `complete` / `failed`), timestamps and stats
- [x] Atomic manifest writes (write to a temp file, then rename) so a crash never corrupts it
- [x] Content-addressed body store: hash, write once, skip if it already exists
- [x] `requests.jsonl` record: id, page, phase, method, URL, status, request and response headers, MIME type, size, body hash, initiator, timing

**2. Fixtures and test harness**

- [x] Build the fixture sites and a local server for them (see Tests below) before writing capture logic

**3. CLI wiring (`cli`)**

- [x] `s2s capture <url>` with `--out`, `--force`, `--depth`, `--pages`, `--viewports`, `--auth-state`, `--har`, `--ignore-robots`, `--concurrency`
- [x] Progress output per phase (requests seen, bytes stored, chunks discovered), quiet with `--json` for scripting
- [x] Ctrl+C handler: flush the index, mark capture `partial`, close the browser
- [x] First-run check for a browser, with a clear install message

**4. Browser session and recording**

- [x] Launch a context per viewport (desktop 1440×900, mobile 390×844 with a mobile UA) with service workers blocked and `--auth-state` loaded if given
- [x] Record every response through context-level listeners, including iframes and workers; skip bodies of redirects and failed requests but still log them
- [x] Tag each request with its phase: `load`, `interact`, `discover`, `crawl`

**5. HTML snapshots**

- [x] Save the raw first HTML response as `pages/<page>/ssr.html`
- [x] Save the hydrated DOM after the page is quiet as `pages/<page>/dom.html`
- [x] Save page metadata (final URL after redirects, title, `<link>` and `<script>` tags in order) as `pages/<page>/page.json`

**6. Lazy-code triggers**

- [x] Scroll the full page in viewport-height steps, waiting for quiet after each
- [x] Hover top-level nav items; click same-page toggles (`aria-expanded="false"`, `<details>`, tab lists)
- [x] Focus the first few inputs to trigger lazily loaded validation or autocomplete code
- [x] Abort main-frame navigations and form submits during this phase; cap total interactions per page

**7. Chunk discovery**

- [x] Scan every captured JS and CSS file for same-origin `.js`, `.mjs` and `.css` references
- [x] Bundler-specific readers:
  - webpack: the public path and chunk-filename map in the runtime chunk
  - Next.js: `_buildManifest.js` and `_ssgManifest.js`
  - Vite/Rollup: `modulepreload` links and `__vite__mapDeps` arrays
  - Import maps and `<link rel="preload">`
- [x] Fetch new URLs through the same context (same cookies and headers), then rescan what came back; repeat until nothing new appears, with a cap on rounds and files
- [x] Also fetch `<file>.map` for every JS and CSS file and store hits (Stage 2 parses them; capture only collects them)

**8. Crawl (optional)**

- [x] Follow same-origin links up to `--depth` and a max page count, or read a list from `--pages`
- [x] Normalize URLs (drop fragments and tracking parameters, dedupe trailing slashes) so one page isn't captured many times
- [x] Run steps 4–7 per page, reusing the body store

**9. Origin classification**

- [x] Tag each request as `first-party`, `cdn-library`, `analytics-ads`, `fonts` or `media`, using registrable domain, MIME type and a maintained host list
- [x] Extract package name and version from known CDN URL patterns (jsdelivr, unpkg, cdnjs, esm.sh, skypack) into `raw/cdn-packages.json`

**10. Runtime probe**

- [x] Run a probe in each page after quiet: framework globals and versions (`React.version`, `__NEXT_DATA__`, `__remixContext`, `__NUXT__`, `jQuery.fn.jquery`, Vue and Svelte markers), `data-*` attribute fingerprints, and loaded `document.styleSheets` origins
- [x] Write results to `raw/runtime.json`, one entry per page and viewport

**11. Screenshots**

- [x] Full-page screenshot per page and viewport, with animations disabled and reduced motion on, so the Stage 5 verify diff isn't noisy

**12. Politeness**

- [x] Check robots.txt before each page; honour crawl delays
- [x] User agent: the browser's own UA with `s2s/<version> (+https://github.com/Rosdal/s2s)` appended
- [x] Apply concurrency and per-page delay limits to discovery and crawl fetches

## Output

After a capture, this is everything later stages may read. Nothing outside `raw/` and `manifest.json` is written yet.

```
<workspace>/
├── manifest.json            capture: complete, options, stats
└── raw/
    ├── requests.jsonl       one line per request, all pages and phases
    ├── bodies/<sha256>      response bodies, deduplicated
    ├── maps/                source maps found next to JS/CSS (unparsed)
    ├── pages/<page-slug>/
    │   ├── ssr.html         first HTML response
    │   ├── dom.html         hydrated DOM
    │   └── page.json        final URL, title, ordered tags
    ├── screenshots/<page-slug>/desktop.png, mobile.png
    ├── runtime.json         probe results per page and viewport
    ├── cdn-packages.json    packages read from CDN URLs
    ├── discovery.json       chunk URLs found, by source and round
    └── capture.har          only with --har
```

## Amended during execution

- **Expected chunk set.** "100% of the JS and CSS chunks" is measured against every JS/CSS file that another served file references, by name or by content hash. Turbopack emits a `/_app` page-loader chunk that nothing references, so no browser or reader can reach it.
- **Blind `.map` probing** stops on an origin after 25 misses in a row with no hit; maps named by a `sourceMappingURL` comment or `SourceMap` header are still fetched. On docusaurus.io all ~2,000 blind probes were 404s. Probing covers first-party files only.
- **Discovery** runs once per viewport, after that viewport's pages, rather than after each page; the result is the same set, fetched once.
- **CDN mocking** in the `cdn-libs` tests uses Playwright routing through an `onContext` hook in the core API, since a local server can't answer for `https://cdn.jsdelivr.net`.
- **Ctrl+C** is tested through an `AbortSignal` in core and an injected interrupt handler in the CLI; sending SIGINT to a child process isn't reliable on Windows.
- **Extra flags** beyond the list above: `--max-pages`, `--delay`, `--quiet-ms`, `--phase-timeout`, `--json`.
- **Unknown third-party scripts and styles** are tagged `cdn-library`; other unknown third-party requests `analytics-ads`, since the five classes have no "other".
- Per-site notes live in `docs/capture-notes/`.
